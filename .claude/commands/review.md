Review a pull request thoroughly — understand intent, check implementation quality, flag issues.

PR to review: $ARGUMENTS

Steps:
1. Read the PR title, description, and linked issues
2. Examine every changed file in the diff
3. Check: does the implementation match the stated intent?
4. Look for: bugs, missing tests, security issues, performance regressions, breaking changes, documentation gaps
5. Check consistency with the rest of the codebase style and patterns
6. Provide inline comments for specific issues (file:line)
7. Give a final verdict: Approve / Request Changes / Needs Discussion
